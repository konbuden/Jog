# My Running Coach — Release 0.4.0

Apple Healthのランニングを日本語のダッシュボードと走力分析画面で振り返る、個人用Webアプリ。React / strict TypeScript / Vite / Dexieで構築しています。

**公開アプリ：[My Running Coach](https://konbuden.github.io/Jog/)**

## 起動

Node.js 24 LTS、npmを使用します。

```sh
npm ci
npm run dev
```

表示先：`http://localhost:5173/Jog/`。

本番ビルドの確認：

```sh
npm run build
npm run preview
```

表示先：`http://localhost:4173/Jog/`。ファイルを直接開く方式には対応しません。公開時はHTTPSが必要です。ローカルではlocalhostを使用してください。

## 使い方

1. iPhoneの「ヘルスケア」→プロフィール→「すべてのヘルスケアデータを書き出す」でZIPを保存します。
2. 「データをインポート」からZIPか展開済みの`export.xml`を選択します。通常は新規記録だけが対象です。既存の追加指標・コースを補う場合のみ「既存記録の不足詳細も追加する」にチェックします。
3. 新規・重複・除外件数、ファイル内の期間と新規対象期間、警告を確認して「保存する」を押します。キャンセルもできます。
4. 各画面の「対象月」で単月・複数月（開始月〜終了月）・全期間を選びます。集計・グラフ・履歴すべてに反映します。走力分析の距離・日付・心拍条件も併用できます。
5. 走力分析の記録行にある「詳細を見る」で、コースや追加指標を確認します。元データにない値は「データなし」と表示します。

Release 0.2では次の4機能を追加しています。

- **カレンダー**：ダッシュボードで日別の距離・回数と月曜始まりの週計を確認。日付を選ぶと分析画面と共通の詳細ポップアップを表示します。同日の複数ランは切り替えられ、閉じる/ESCでカレンダーに戻ります。複数月ではカレンダー内の月を切り替えられます。
- **期間比較**：走力分析の「期間比較」を開き、期間A/Bを指定。前月・直近3か月・前年同期のプリセットも使えます。比較期間は上の対象月/日付指定と独立し、距離帯・心拍帯の条件を共通適用します。
- **目標変更**：画面上部の「目標・バックアップ」→「目標設定」。月間距離、任意の週間回数・年間距離を保存できます。月間目標は過去を含む全期間に適用します。月/週は選択月の実績と目標値、達成月数/週数を表示します。月曜始まりの部分週も範囲内だけ集計します。年間だけは選択月に関係なく今年の全実績を使います。
- **バックアップ**：同じ設定内の「バックアップ」でJSONを書き出します。別端末/ブラウザではそのJSONを選び、新規・重複・詳細追加件数と対象期間を確認して復元してください。既存記録は削除せず、目標設定を復元するか選べます。

バックアップは健康・位置情報を含む**平文ファイル**です。保存先・共有範囲を確認してください。Run・追加指標・表示用GPSコース・振り返り・目標を含み、生XML/ZIP/GPXは含みません。200 MB・10万ラン・1万コースまで対応。読み込み/書き出しはWorker内で処理します。同じファイルの再復元でランを重複させず、不正ファイル/キャンセル/保存失敗では本データを変更しません。暗号化、置換復元、自動クラウド同期はありません。

追加指標はWorkout内の歩数、平均ケイデンス、アクティブ消費エネルギー、ランニングパワー、歩幅、接地時間、上下動、最大心拍、上昇高度、屋内・屋外の情報に対応します。ケイデンスの明示値がなく、Workout内の歩数がある場合は歩数÷Workout時間から算出し、その旨を表示します。独立したRecordを時刻から結び付けて補完しません。

コースはWorkoutRouteのFileReferenceとZIP内GPXの参照先が一致する場合に限り保存します。GPS軌跡を背景地図なしで表示し、外部地図サービスにはアクセスしません。XML単体ではコース座標を取得できません。**以前取り込んだ記録には「既存記録の不足詳細も追加する」を選んで、元のZIPを再インポートしてください。** 保存前に詳細追加件数を確認でき、記録を重複させず不足情報だけを追加します。

サンプルデータは自動投入しません。初回は空の画面です。健康情報はブラウザ内で処理し、IndexedDBに保存します。生XML/ZIPは保存しません。本番ではCSPの`connect-src 'none'`で通信も禁止しています。テレメトリや外部フォントは使用しません。アプリの静的ファイル取得には通常のHTTPS通信が発生します。

## 分析・アドバイス（Release 0.4）

走力分析の下部と、カレンダーの日付選択後の詳細ポップアップの最下部で「分析する」を押します。選択したランについて、10km走行能力・ペース管理能力・運動中の余力、総括・良い点・改善点・翌日回復の確認・アドバイスを表示します。両画面は同じ記録・振り返り・全保存履歴を使います。

「振り返り・区間ラップを入力する（任意）」で、走行目的、終了時のきつさ（RPE 1〜10）、終盤に負荷を下げた/上げた意図、追加2〜3kmの余裕、翌朝の疲労、違和感を記録できます。「振り返りを保存する」でこのブラウザのIndexedDBに保存します。入力変更で古い結果を消し、「分析する」で再計算。未保存の入力でも分析できます。別タブの更新は古い入力で上書きせず、読み直して確認します。

区間ラップは元の記録を確認し、1行1区間で`距離km, 時間m:ssまたはh:mm:ss, 平均心拍bpm（任意）, 平均パワーW（任意）`を入力します。最初から最後までの全区間が必要です。最大100件。距離合計の差は100mまたは2%、時間合計の差は30秒または5%まで検証します。**現行のXML取り込みは全体平均の統計を保存しており、区間ラップは自動取得していません。** 未入力を推測で埋めません。

参考点は過去の順位方式を廃止しました。10kmは実際の完走実績、中盤のペース管理は区間ペースの変動、余力は本人申告のRPEを根拠にします。総合点は3観点が揃う場合のみ40%/30%/30%で集計し、不足時は「評価保留（確認済み観点数/3）」と表示します。短いジョグ、心拍が高い日、過去で最も遅い日という理由だけで総合0点にはしません。点数は説明用の参考ルーブリックで、妥当性が検証された医学的・絶対走力のモデルではありません。

意図的な終盤減速は本人申告とラップを確認し、失速と決めつけません。速いペースと心拍上昇が同時にある場合は、走力向上だけでなく強度上昇も説明します。平均/最高心拍から余力・最大心拍・翌日の回復を推定しません。翌朝未確認なら回復の評価を保留します。アドバイスは今回の実績・意図・体感・設定月間目標を根拠にし、不明な心拍ゾーンや個別の練習強度は処方しません。

振り返りはバックアップv2の`reviews`に含みます。旧バックアップも読み込め、既存の振り返りは上書きせず不足分だけ復元します。振り返り入りバックアップの復元にはv0.4以降を使用してください。古いアプリでは新形式の復元を拒否し、振り返りが失われることを防ぎます。全データ削除では振り返りも消去します。

両画面の表・詳細には10kmあたりの時間（等速換算）を表示します。分析結果は保存せず、健康情報を外部GPT/AI/APIへ送信しません。詳しい基準は[release-0.4.md](release-0.4.md)を参照してください。

## 取り込み済みデータの全削除

「データをインポート」→「取り込み済みデータを全削除」で件数を確認し、「削除対象を確認しました」にチェックしてから「全データを削除する」を押します。このブラウザ内の全期間のラン・コース・振り返り・取り込み履歴・一時データが対象です。目標設定と端末に書き出したバックアップは残ります。キャンセル・別タブの処理中・確認後の件数変化では削除しません。

既に登録された重複を自動削除する更新ではありません。整理する場合は必要なデータをバックアップし、全削除後に元のApple Health ZIP/XMLを取り込み直してください。重複を含むバックアップを復元すると、その重複も戻ります。削除後は同じファイルから再取り込みできます。

## 数値のルール

- 日時はUTC保存、表示・月集計・日付条件は日本時間（Asia/Tokyo）です。
- 月をまたぐランは開始月に計上します。月間距離目標は初期100kmで変更できます。複数月では月間目標×対象月数が期間目標です。
- 平均ペースは総時間÷総距離、平均心拍は取得済みランだけの時間加重平均です。
- 10km等速換算は同じ平均ペースで10km走った場合の時間で、予測記録ではありません。
- 心拍は同じWorkout内の平均統計だけを使用します。独立した心拍Recordを時刻から紐付けず、不明な心拍は「データなし」と表示します。
- 同一ファイルは内容の指紋で判定してXML/ZIPの再解析を省略します。作り直したZIPや機器表記が変わるエクスポートは既存記録とも照合し、同じランとファイル内の重複行を追加しません。通常は既存の詳細・コースも処理しません。距離・時間・心拍の内容が変わっている場合は既存値を保持し警告します。明示的な詳細追加モードでも既存値を上書きせず、欠けている項目だけを補います。
- 各画面のグラフも選択した対象月に揃えます。期間指定は100年（1,200か月）までです。記録表は絞り込み結果全体を20件ずつ表示します。

詳細：[architecture.md](architecture.md)、[data-specification.md](data-specification.md)。

## 保存・対応範囲

保存先は端末・ブラウザ・オリジンごとに独立し、同期しません。ブラウザのデータ削除や保存領域の回収で記録が消えることがあります。元のエクスポートを保管してください。ブラウザを変えた場合は元ファイルから再取り込みできます。

選択するXML・ZIPはどちらも200 MB（200,000,000バイト）まで、ZIP展開後のXMLは5 GB（5,000,000,000バイト）までです。ZIPは10,000エントリ・管理情報8 MiBまで。通常ZIPとZIP64のstored/deflateに対応します。暗号化・分割ZIP・複数export.xmlは非対応です。展開後のXMLをファイルとして丸ごと保存せず、ランニング記録だけを逐次抽出するため、5 GB分の空き領域を必須とはしません。解析時間と保存容量は記録数・端末性能に依存します。構文不正のXMLは一部だけ保存しません。未知の単位や欠損データは理由を表示します。

コースは1ラン8 GPX・64区間、GPXは展開後1ファイル20 MB・全体200 MBまで。GPS点は表示用に約2,000点へ間引き、区間の切れ目をつなぎません。コースだけが不正・欠損の場合は警告して走行記録を残します。座標は別のIndexedDBテーブルで保存し、詳細表示時だけ読み込みます。

安定したUUIDがないランで距離等が後から変更されると、別の記録になる場合があります。異なる出典・機器の同一活動は自動統合しません。XMLの距離は`totalDistance`またはWorkout内の対応する距離統計が必要です。

詳細な仕様・実装タスク・リスクは[release-0.2.md](release-0.2.md)、差分取り込み・全削除の仕様は[release-0.2.1.md](release-0.2.1.md)を参照してください。

対応API：Web Worker、Web Crypto、IndexedDB、Web Locks、dialog。モダンブラウザを想定しています。GitHub ActionsでChromium・Firefox・WebKitのE2Eを公開条件にしています。iPhone・iPad実機は未検証です。CIでは3ブラウザの成功を公開条件にしています。

## テスト

```sh
npm test
npm run test:large
npx playwright install --with-deps chromium firefox webkit
npm run test:e2e
```

E2Eは本番ビルドに対して実行します。システムのChromiumだけで検証する場合：

```sh
PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium npm run test:e2e -- --project=chromium
```

`test:large`は100 MiBの合成XMLとZIPに加え、200 MBちょうどのXMLとZIP、5 GBちょうどに展開されるZIP64を一時ディレクトリに生成して解析し、終了後に削除します。計測結果はOSの一時ディレクトリの`my-running-coach-performance.json`と`my-running-coach-zip64-performance.json`へ保存します。詳細は[validation-report.md](validation-report.md)を参照してください。

合成テストデータは`tests/fixtures/synthetic/`に限定しています。実データをリポジトリ、テスト、CI、スクリーンショットに入れないでください。XML/ZIPと標準名のバックアップJSONはgitignoreし、合成fixtureのXMLだけを例外としています。実際のバックアップJSONをリポジトリへ追加しないでください。

## GitHub Pagesへの公開

アプリ名・パッケージ名はMy Running Coach / my-running-coach、公開先は[`konbuden/Jog`](https://github.com/konbuden/Jog)です。Viteのbaseは`/Jog/`です。

1. GitHubの`konbuden/Jog`リポジトリを使用します。
2. Settings → Pages → Build and deployment → Sourceを **GitHub Actions** に設定します。
3. このプロジェクトをmainブランチへpushします。
4. Actionsの「Validate and deploy Pages」を確認します。型検査・Vitest・大容量解析・3ブラウザE2Eのいずれかが失敗すると公開ジョブは実行されません。
5. 成功後、Actionsに表示されるPages URLでダッシュボード、分析への直接アクセス、ZIP/XML取り込みを確認します。

ワークフローは`dist/`だけをアップロードします。IndexedDBや元の健康情報は公開成果物に含まれません。独自ドメイン・別名リポジトリを使う場合はViteのbaseとテストURLも変更してください。
